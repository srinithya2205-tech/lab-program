# Portfolio Intelligence Assistant — Python backend

A small FastAPI service that answers questions about Sri Nithya's portfolio.

**It is not an LLM.** Answers are assembled by a deterministic Python engine
(`app/engine.py`) from `data/portfolio.json`. If the portfolio doesn't contain
something (e.g. work experience), the assistant says so instead of guessing.
No API keys, no external calls.

```
backend/
├── app/
│   ├── main.py        FastAPI app: /health, /portfolio, /ask, CORS
│   ├── engine.py      Question-answering engine (standard library only)
│   └── schemas.py     Pydantic request/response models + validation
├── data/portfolio.json   Source of truth (copied from the live site)
├── tests/
│   ├── test_engine.py    27 engine tests (no dependencies needed)
│   └── test_api.py       API tests (need requirements-dev.txt)
├── requirements.txt / requirements-dev.txt
├── Dockerfile / Procfile
└── .env.example
```

## Endpoints

| Method | Path         | Purpose                                                       |
|--------|--------------|---------------------------------------------------------------|
| GET    | `/health`    | Liveness check → `{"status":"ok", ...}`                       |
| GET    | `/portfolio` | The full portfolio JSON the assistant answers from            |
| POST   | `/ask`       | Body `{"question": "..."}` (1–500 chars) → answer + sources   |
| GET    | `/docs`      | Interactive Swagger UI (auto-generated by FastAPI)            |

`/ask` response:

```json
{
  "answer": "The Projects section features 3 projects ...",
  "matched": true,
  "topics": ["projects"],
  "sources": ["Projects › Air Quality Index (AQI) Analysis", "..."],
  "suggestions": ["Tell me about the AQI project", "..."]
}
```

`matched: false` means the portfolio had nothing relevant (the answer says so).
Empty, whitespace-only, missing, wrong-type or >500-char questions return **422**.

## Run locally

Requires Python 3.10+.

```bash
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env               # optional for local runs

uvicorn app.main:app --reload --port 8000
```

Try it:

```bash
curl http://localhost:8000/health
curl http://localhost:8000/portfolio
curl -X POST http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "Which projects use Python?"}'
```

## Tests

```bash
cd backend
python -m unittest tests.test_engine -v    # engine tests — no installs needed
pytest -v                                  # engine + API tests (needs requirements-dev.txt)
```

## Production

The app is a standard ASGI application, deployable on its own:

```bash
uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 2 --proxy-headers --forwarded-allow-ips "*"
```

**Render / Railway / Fly.io (no Docker):** set the root directory to `backend`,
build command `pip install -r requirements.txt`, start command as above (the
`Procfile` already contains it).

**Docker:**

```bash
cd backend
docker build -t portfolio-api .
docker run -p 8000:8000 -e ALLOWED_ORIGINS=https://srinithya2205-tech.github.io portfolio-api
```

### Environment variables

| Variable          | Default                                  | Meaning                                                     |
|-------------------|------------------------------------------|-------------------------------------------------------------|
| `ALLOWED_ORIGINS` | GitHub Pages origin + localhost dev URLs | Comma-separated browser **origins** allowed to call the API |
| `PORT`            | `8000`                                   | Port to listen on (most hosts set this for you)             |
| `WEB_CONCURRENCY` | `2`                                      | uvicorn worker processes                                    |

> **CORS gotcha:** an origin has no path. Your site lives at
> `https://srinithya2205-tech.github.io/lab-program/`, but the origin to allow is
> `https://srinithya2205-tech.github.io`. Your deployed API must be served over
> **HTTPS**, otherwise browsers block calls from your HTTPS site (mixed content).

GitHub Pages only hosts static files, so this backend must be deployed to a
separate service. Free tiers sleep when idle, so the first request after a quiet
period can take 30–60 seconds (the UI shows a "waking up" message).

## Keeping answers accurate

`data/portfolio.json` is the only source of facts. When you change the website
(new project, new certificate…), update that file and redeploy — the assistant
can never know more than this file says. `experience` and `achievements` are
empty on purpose because the live portfolio has no such sections; the assistant
says so honestly when asked.
